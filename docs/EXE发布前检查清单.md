# EXE / 便携包发布前检查清单（团队培训包）

发布负责人至少完整跑 **2 遍** 下列步骤；第二遍在另一台 **干净 Windows 电脑** 上做。

## 1. 构建与环境

- [ ] **打包前**已关闭本机正在运行的 **`ZhaGouData.exe`**（否则会占用 `release\win-unpacked\resources\app.asar`，构建必失败）。
- [ ] 已执行 `npm run build:desktop`，`release\win-unpacked\ZhaGouData.exe` 存在（并尽量确认同目录 `ZhaGouData-win-x64.zip` 已打出，便于发给团队）。
- [ ] 已执行 `npm run verify:desktop-build`，脚本报 **OK**。
- [ ] 本机已执行过一次：`npx playwright install chromium`（用于网页回退路径）。

## 2. 首次启动

- [ ] 双击 exe 后 **10～45 秒内** 界面能打开（首次可能略慢）。
- [ ] 浏览器里（或内置窗口）任务页 **Runner 地址** 自动指向 `http://127.0.0.1:8794`（或你包内约定端口）。
- [ ] 另开浏览器访问 `http://127.0.0.1:8794/health` 返回 JSON 且 `ok: true`。

## 3. 功能冒烟（小数据）

- [ ] **数据页**：上传含 **20 条**号码的 txt，能导入。
- [ ] **任务页**：选 **2～3 个在线端口**，并发填 **4**，模式 **混合**，能 **启动批次**。
- [ ] **2 分钟内**进度有前进；结果区有 `手机号：QQ` 或 `手机号：无结果` 文本（允许部分为限流失败，但不能全卡 0）。
- [ ] **停止批次** 后，不再增长 processed。

## 4. 限流与误判（培训重点）

- [ ] 故意把并发拉高到不合理值时，界面或日志能区分 **「被拦」** 与 **「无结果」**（不能把 429 全记成无 QQ）。
- [ ] 出现大量失败时，**减并发 / 换代理** 后，成功率有回升。

## 5. 打包完整性

- [ ] 解压目录里除 exe 外，还有 `resources` 等结构；**不要只拷单文件**到 U 盘缺目录。
- [ ] 杀毒软件未误删 `resources\desktop-bundle` 下文件（企业环境常见）。

## 6. 交付物

- [ ] 附带 `docs/一天20万操作说明.md` 打印版或 PDF 发给团队。
- [ ] 附带 `.env.example` 说明如何改成正式 `.env`（不写敏感值进教材）。
